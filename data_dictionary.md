# Data dictionary — кейс 2 «Кредитный конвейер»

## Как заполнять

В `applications.csv` 14 колонок. Все нужно описать. Одна строка — образец.
Для каждой колонки укажи: тип, обязательность, ограничение, пример (из CSV), код ошибки (если валидируется), комментарий.

Обозначения:

- **Обяз.** — `да` (клиент обязан передать), `да (сервер)` (генерирует/вычисляет сервис), `условно` (зависит от решения), `нет` (необязательно).
- **Код ошибки** — коды с пометкой `*` — это `error_code` ответа 422 (валидация). Они не являются значением `Decision.reason` и в CSV не встречаются, потому что в данных нет таких строк.
- **Причина решения** — коды без пометки попадают в `Decision.reason`. Единственный код «нужны данные» — `MISSING_INCOME`; пустые значения остальных обязательных полей отбиваются ошибкой 422 до запуска конвейера.

## Образец (не трогать)

|---|---|---|---|---|---|---|
| app_id | string | да (сервер) | `app_NNNN` | app_0001 | — | генерируется сервисом |

## Справочники (enum-значения)

### 1. `employment` — 5 значений

| Значение | Баллы скоринга | Смысл |
|---|---|---|
| `employed` | 25 | Наёмный работник, стабильный доход |
| `self-employed` | 20 | Самозанятый/ИП, доход менее предсказуем |
| `retired` | 10 | Пенсионер, фиксированный доход |
| `student` | 5 | Студент, дохода обычно нет |
| `unemployed` | 0 | Безработный → `INVALID_EMPLOYMENT` |

### 2. `family` — 3 значения

| Значение | Баллы | Смысл |
|---|---|---|
| `married` | 15 | Есть второй доход / устойчивое домохозяйство |
| `children` | 10 | Есть иждивенцы, но выше ответственность и стабильность |
| `single` | 10 | Нет подтверждённой финансовой поддержки |

### 3. `decision` — 4 значения

| Значение | Когда | Что видит клиент |
|---|---|---|
| `APPROVED` | Все правила пройдены, `score ≥ 60` | «Предварительно одобрено» + сумма/срок/ставка |
| `REFUSED` | Сработало правило отказа | Причина человеческим языком |
| `NEED_MORE_DATA` | `income` пуст или таймаут БКИ/СМЭВ | «Укажите доход» / «Попробуйте позже» |
| `MANUAL_REVIEW` | Зарезервирован; правилами не выдаётся | «Заявка на ручной проверке» |

### 4. `smev_status` — 4 значения

| Значение | Когда | Влияние на решение |
|---|---|---|
| `MATCH` | Данные совпали (9 из 10) | Продолжаем |
| `MISMATCH` | `md5(client_id) % 10 == 0` | `REFUSED` / `SMEV_MISMATCH` |
| `TIMEOUT` | Ответ > 3 с даже после retry | `NEED_MORE_DATA` / `EXTERNAL_TIMEOUT` |
| `NOT_CALLED` | До СМЭВ не дошли (упали на валидации) | Решение уже принято раньше |

## Критерий приёмки

- [ ] Все 14 колонок описаны
- [ ] Для age указан диапазон 18–70 и AGE_OUT_OF_RANGE
- [ ] Для income — > 0 и MISSING_INCOME
- [ ] Для employment — справочник из 5 значений и INVALID_EMPLOYMENT
- [ ] Для passport_hash — SHA-256 (усечённый до 16 hex), оригинал не хранится
- [ ] Для dti — формула (аннуитет / доход), порог 0.5
- [ ] Для bki_score — диапазон 300–850, < 500 = отказ
- [ ] Для smev_status — MATCH / MISMATCH / TIMEOUT / NOT_CALLED
- [ ] Комментарий объясняет «зачем поле»

## Подсказки

- employment — enum из 5: employed, self-employed, student, retired, unemployed.
- family — enum из 3: single, married, children.
- decision — enum из 4: APPROVED, REFUSED, NEED_MORE_DATA, MANUAL_REVIEW.
- passport_hash — 16 hex-символов, не оригинал паспорта.
- dti — число с 2 знаками, от 0 до бесконечности, порог 0.5.
