# Информационная безопасность — кейс 2 «Кредитный конвейер»

## Как заполнять

Даны 2 угрозы из 6, 2 меры из 6, 2 строки RBAC из 6, 2 поля аудита из 8.
Заполни остальное. В разделе «Защита данных» ответь на вопросы.
Каждая мера должна быть привязана к угрозе по ID.

## 1. Модель угроз (заполни 4 из 6)

|ID|Угроза|Актив|Вероятность|Ущерб|Источник|
|-|-|-|-|-|-|
|U-1|Дискриминация по полу/национальности|репутация, закон|средняя|высокий|предвзятость правил|
|U-2|Утечка ПДн (паспорт, доход)|данные клиента|средняя|высокий|логи, ошибки|
|U-3|Подделка данных заявки|финансовые ресурсы|высокая|высокий|мошенник|
|U-4|Обход скоринга подбором суммы|лимиты и правила отказа|средняя|средний|недобросовестный заёмщик|
|U-5|Отсутствие аудита решения|доверие, рассмотрение споров|средняя|высокий|сбой, внутренний нарушитель|
|U-6|Таймаут БКИ/СМЭВ|корректность решения|средняя|высокий|ошибка сервиса, сети|

**Подсказки для U-3…U-6:**

* подделка данных заявки (мошенник);
* обход скоринга подбором суммы;
* отсутствие аудита решения;
* таймаут БКИ/СМЭВ → неверное решение.

## 2. Меры защиты (заполни 4 из 6)

|ID|Угроза|Мера|Остаточный риск|
|-|-|-|-|
|U-1|дискриминация|запрет пола/национальности в правилах; полей «пол» и «национальность» нет в схеме заявки (`additionalProperties: false`); скоринг использует только 5 признаков|низкий|
|U-2|утечка ПДн|из паспортных данных хранится только `passport_hash`; доход хранится в заявке, но маскируется в логах; в `audit.log` и `external.log` ПДн нет|низкий|
|U-3|подмена данных заявки|личность сверяется с СМЭВ; при `MISMATCH` — отказ; доход и занятость подтверждаются документами по запросу; создание заявки, ошибка проверки и решение фиксируются в аудите|средний|
|U-4|обход скоринга|жёсткие лимиты считаются на сервере по формулам; в аудите остаётся `client_id`, поэтому видны повторные заявки одного клиента|средний|
|U-5|отсутствие аудита|журнал append-only; событие на каждый шаг обработки с полями `event_id`, `app_id`, `client_id`, `actor`, `at`; удаление запрещено всем ролям|низкий|
|U-6|таймаут БКИ/СМЭВ|таймаут 3 с и один повтор через 0,5 с; при неудаче — `NEED_MORE_DATA` с причиной `EXTERNAL_TIMEOUT`, без автоодобрения и без отказа; каждая попытка пишется в `external.log`|низкий|

**Подсказка:** каждая мера должна ссылаться на ID угрозы из раздела 1.

## 3. RBAC — матрица прав (заполни 4 строки из 6)

|Действие|Клиент|Сервис (system)|Андеррайтер|Аудитор|
|-|-|-|-|-|
|Подать заявку|да|да|нет|нет|
|Посмотреть решение|да|да|да|да|
|Пересчитать решение|нет|да|да|нет|
|Читать аудит|нет|да|да|да|
|Менять правила скоринга|нет|нет|нет|нет|
|Удалять аудит|нет|нет|нет|нет|

**Подсказки:**

* Клиент видит только свои заявки (по `client_id`).
* Аудитор — read-only.
* Андеррайтер может пересчитать, но не удалить историю.
* Аудит append-only: никто не может удалить.

## 4. Аудит — структура события (заполни 6 полей из 8)

|Поле|Тип|Пример|Зачем|
|-|-|-|-|
|event_id|string|evt_0001|уникальный ID события|
|app_id|string|app_0001|привязка к заявке|
|client_id|string|cli_0001|псевдонимный ID клиента: по нему видны повторные заявки (U-4) и ограничивается доступ клиента к своим заявкам; прямых ПДн не содержит|
|step|enum|decision_made|шаг обработки: application_created / validation_failed / decision_made / recalculated|
|decision|enum|APPROVED|принятое решение: APPROVED / REFUSED / NEED_MORE_DATA / MANUAL_REVIEW; пусто для `application_created`|
|reason|string|AMOUNT_LIMIT|код причины из `08_reasons.md`; для `validation_failed` — код поля из `data_dictionary.md`; пусто при `APPROVED` и `application_created`|
|score|number|65|итоговый балл скоринга; пусто, если скоринг не выполнялся|
|dti|number|0.39|долговая нагрузка; пусто, если не рассчитывалась|
|external|array|`[{"service":"SMEV","status":"SUCCESS","result":"MATCH"},{"service":"BKI","status":"SUCCESS","result":"score=720, delinquency=false"}]`|краткий след вызовов БКИ/СМЭВ; пусто, если вызовов не было; полные детали — в `external.log`|
|actor|enum|system|кто совершил действие: system / underwriter|
|at|string (ISO 8601)|2026-11-05T16:42:46Z|время события|

**Подсказки для остальных полей:**

* `step` — enum: `application_created` / `validation_failed` / `decision_made` / `recalculated`.
* `decision` — `APPROVED` / `REFUSED` / `NEED_MORE_DATA` / `MANUAL_REVIEW`; пусто для `application_created`.
* `reason` — код из `08_reasons.md`; для `validation_failed` — код поля из `data_dictionary.md`.
* `score` — итоговый балл скоринга; пусто, если скоринг не выполнялся.
* `dti` — долговая нагрузка; пусто, если не рассчитывалась.
* `external` — массив вызовов: `service` (`BKI` / `SMEV`), `status` (`SUCCESS` / `TIMEOUT` / `ERROR`), `result` (краткий ответ без ПДн: для СМЭВ `MATCH` / `MISMATCH`, для БКИ score и признак просрочки).
* `actor` — system / underwriter.
* `at` — время события (ISO 8601).

**Правила аудита (заполни):**

* Как хранится журнал? — append-only: записи только добавляются, менять и удалять нельзя. В прототипе это файл `audit.log`, одна JSON-строка на событие; в продакшене — хранилище с запретом UPDATE/DELETE.
* Сколько хранится? — 1825 дней (5 лет) по внутренней политике банка: срок нужен для разбора споров по кредитным решениям.
* Содержит ли ПДн? — нет: `client_id` — псевдоним; паспорт, его хеш, ФИО, контакты и доход в журнал не пишутся.
* Кто имеет доступ на чтение? — сервис (system), андеррайтер и аудитор; клиент аудит не читает, своё решение видит через ответ приложения.

## 5. Защита данных (ответь на вопросы)

**Что нельзя хранить и почему?**

* PAN / номер карты — для оценки заявки не нужен; при утечке прямой финансовый ущерб, а хранение карточных данных требует отдельной сертификации.
* Оригинал паспорта — при утечке позволяет оформлять кредиты на клиента. Храним только `passport_hash`.
* Полное ФИО + телефон + адрес — вместе однозначно идентифицируют человека и позволяют мошенничество; для решения не нужны.
* Пол, национальность, религию — не собираем и не храним: они не нужны для решения и создают риск дискриминации (U-1).

**Что можно хранить?**

* `passport_hash` — 16 hex-символов; в прототипе это усечённый SHA-256, в продакшене — HMAC-SHA256 с секретным ключом. Обычный SHA-256 перебирается по пространству паспортных номеров, поэтому в продакшене нужен ключ. По хешу сверяем клиента с СМЭВ и БКИ, не раскрывая паспорт.
* `client_id` — псевдонимный идентификатор клиента; нужен для связи заявок и ограничения доступа клиента к своим заявкам. Сам по себе личность не раскрывает, прямых ПДн не содержит.
* `income` — нужен для скоринга, DTI и лимита; хранится в заявке, но в логах маскируется.
* `decision`, `reason`, `score`, `dti` — результат решения; нужен для объяснимости и аудита, прямой идентификации человека не даёт.

**Маскирование логов — приведи пример:**

До: `app_id=app_0001 income=120000 passport=<номер> decision=APPROVED`
После: `app_id=app_0001 income=*** passport_hash=f727…2224 decision=APPROVED`

## 7. Соответствие CIA-триаде (заполни)

|Принцип|Как реализован в кейсе|
|-|-|
|Конфиденциальность|Передача данных по TLS; вместо паспорта только `passport_hash` (в продакшене HMAC-SHA256 с ключом); в логах нет ПДн|
|Целостность|append-only аудит с `actor` и `at`; удаление запрещено всем ролям; серверные лимиты; валидация входа до расчёта|
|Доступность|таймаут 3 с и один повтор для БКИ/СМЭВ; fallback `NEED_MORE_DATA` вместо падения конвейера; ошибка одной заявки не останавливает обработку остальных|

**Подсказка:** конфиденциальность — TLS + хеширование; целостность — аудит + неизменяемость; доступность — таймауты + fallback.

## 8. Критерий приёмки

- [ ] 5+ угроз с вероятностью и ущербом
- [ ] 5+ мер, каждая привязана к ID угрозы
- [ ] RBAC: 4 роли, 6 действий
- [ ] Аудит: 8+ полей, append-only
- [ ] Запрет дискриминационных признаков
- [ ] ПДн: только `passport_hash`, логи маскируются
- [ ] Секреты не в Git, не в логах
- [ ] Соответствие CIA объяснено

## 9. Типичные ошибки (минус баллы)

1. «У нас всё безопасно» — без угроз и мер.
2. Угрозы без оценки вероятности/ущерба.
3. Меры не привязаны к угрозам по ID.
4. Нет RBAC — все роли одинаковы.
5. Аудит есть, но нет полей `actor` и `at`.
6. Оригинал паспорта хранится «в зашифрованном виде» — нельзя, только hash.
7. Секреты в коде (`SECRET = "abc123"`).
8. Нет связи с CIA-триадой.
